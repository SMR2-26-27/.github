## 📂 Cómo estarán organizadas las prácticas

La mayor parte del trabajo del curso estará organizado mediante **repositorios de GitHub**.

Cada práctica tendrá normalmente su propio repositorio e incluirá:

* 📄 un `README.md` con el enunciado y las instrucciones;
* 💻 los archivos necesarios para comenzar;
* 📁 una estructura de carpetas preparada cuando sea necesaria;
* 🔗 enlaces y recursos útiles;
* ✅ las indicaciones sobre lo que hay que realizar y entregar.

> [!IMPORTANT]
> **Lee siempre el `README.md` antes de empezar una práctica.**

Muchas dudas se resuelven simplemente leyendo atentamente el enunciado antes de comenzar.

## 🔄 Flujo de trabajo

Nuestro flujo habitual será aproximadamente:

```text
Repositorio en GitHub
        ↓
GitHub Desktop
        ↓
Clonar repositorio
        ↓
Visual Studio Code
        ↓
Editar · probar · corregir
        ↓
Commit
        ↓
Push
        ↓
GitHub
```

No hace falta memorizarlo desde el primer día.

Después de repetirlo unas cuantas veces, se convertirá en algo completamente rutinario.

## 🧭 Algunas reglas sencillas

1. 📖 **Lee el enunciado antes de empezar.**

2. 💾 Trabaja habitualmente sobre **tu propio repositorio** de cada práctica.

3. 📝 Haz *commits* frecuentes y utiliza mensajes que expliquen brevemente lo que has hecho.

   ```text
   ❌ cambios
   ❌ cosas
   ❌ commit final

   ✅ Añadido formulario de registro
   ✅ Corregida validación del email
   ✅ Creada barra de navegación
   ```

4. 🔑 **Nunca subas contraseñas, tokens, claves privadas ni otros datos sensibles a GitHub.**

5. 📁 Mantén una estructura de archivos y carpetas razonablemente ordenada.

6. 🔍 Si algo falla, **lee el mensaje de error** antes de preguntar.

   Los mensajes de error no están ahí para fastidiarte. Muchas veces están intentando decirte exactamente qué ha ocurrido.

7. 🧪 **Experimenta.**

   Equivocarse, romper algo y aprender a arreglarlo forma parte del curso.

## 🔐 Y una regla especialmente importante...

En **Seguridad Informática** trabajaremos con herramientas y técnicas que permiten analizar sistemas y redes, detectar vulnerabilidades y comprender cómo pueden producirse determinados ataques.

Todo lo que hagamos tendrá una finalidad exclusivamente **educativa**.

> [!WARNING]
> Las prácticas de seguridad se realizarán únicamente sobre los sistemas, máquinas virtuales, redes y servicios expresamente indicados en cada actividad.

Saber cómo funciona un ataque es una de las mejores maneras de aprender a defenderse de él.

Pero saber hacerlo implica también aprender **cuándo y dónde se puede hacer**.

## 🤖 IA

Durante el curso probablemente utilizaremos también herramientas de **Inteligencia Artificial**.

Podéis utilizarlas para:

* entender conceptos;
* buscar explicaciones alternativas;
* analizar errores;
* obtener pistas;
* documentar código;
* explorar diferentes soluciones.

Pero existe una diferencia importante entre **utilizar una IA para aprender** y **pedirle que haga una práctica que después no sabemos explicar**.

Una regla bastante útil:

> **Si entregas código, debes ser capaz de explicar qué hace.**
